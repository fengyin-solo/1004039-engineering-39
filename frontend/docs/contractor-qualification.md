# 施工队伍资质链路与构建前校验

施工队伍从登记到作业的完整链路、样例准备与构建前校验都集中维护在本目录，
新增资质类型（资质等级、企业、证书）时只改规则 JSON，不用再人工对照多处校验。

## 1. 资质链路（资质等级 / 特种作业证 / 所属企业 / 作业状态）

```text
待审核 ──审核备案──▶ 已备案 ──安排作业──▶ 作业中 ──清退队伍──▶ 已清退
```

| 作业状态 | 所处环节 | 校验内容 | 构建期处理 |
| --- | --- | --- | --- |
| 待审核 | 审核备案（record） | 资质等级已登记在册；所属企业已登记；企业持有队伍填报等级的资质（证企一致） | 不满足则**阻断构建** |
| 已备案 | 安排作业（assign） | 备案条件全部满足；资质等级达到三级及以上；持有限空间作业操作证；全部证书在有效期内 | 不满足则**阻断构建**（避免页面出现安排不了作业的队伍） |
| 作业中 | 安排作业（assign） | 同上，仅用于监控证书过期等风险 | 只**预警**不阻断，队伍状态与数据不被改动 |
| 已清退 | — | 不再校验资质链路 | 跳过 |

要点：

- **资质等级**：`特级/一级/二级/三级` 四档（rank 4→1），安排作业要求三级及以上。
- **所属企业**：企业有自己的可承接资质范围；队伍填报的等级必须落在范围内，否则视为证企不一致。
  「宏图劳务分包有限公司」无施工总承包资质，其名下任何有等级的队伍都不能备案。
- **特种作业证**：字段格式为 `证名(证号:有效期YYYY-MM-DD)`，多证用「、」分隔，例如
  `有限空间作业操作证(AX-1001:2028-06-30)、焊接与热切割作业操作证(AH-1002:2028-03-31)`。
  备案环节不查证书；安排作业时必须持有限空间作业操作证，且所有在册证书均未过期。

## 2. 文件与职责（单一规则源）

| 文件 | 职责 |
| --- | --- |
| `src/data/contractor-rules.json` | **唯一规则源**：资质等级、企业资质范围、证书目录、各环节条件、状态流转、受保护状态 |
| `src/data/contractor-rules.mjs` | 纯函数规则引擎（零依赖），Node 脚本与浏览器共用 |
| `src/data/contractor-rules.d.mts` | 引擎的 TypeScript 类型声明 |
| `src/data/contractor.ts` | 浏览器侧入口，`local-service.ts` 动作拦截用 |
| `src/data/contractor-samples.json` | prepare 环节生成的样例（提交入库，不要手改） |
| `scripts/contractor-sample-spec.mjs` | 标准样例规约 |
| `scripts/contractor-pipeline.mjs` | 样例准备 + 构建前校验流水线（Node 运行） |
| `test/contractor-pipeline.test.mjs` | 引擎、prepare 合并语义、validate 分类、CLI 退出码测试 |

## 3. 流水线命令

```bash
npm run contractor:prepare   # 只跑样例准备（幂等）
npm run contractor:validate  # 只跑构建前校验（修复后单独重跑失败环节）
npm run contractor:pipeline  # prepare + validate 串跑
npm run build                # prebuild 钩子自动先跑 pipeline，校验不过不打包
npm test                     # 规则与流水线测试
```

`validate` 支持 `--date=YYYY-MM-DD` 指定证书有效期基准日、`--samples/--rules` 指定文件。

### 失败输出长什么样

```text
✘ [阻断][已备案队伍 · 安排作业] 队伍 CONT-0004「江堤管网养护小队」
    不满足条件「所属企业持有队伍填报资质等级的施工资质（证企一致）」：
    所属企业「宏图劳务分包有限公司」不持有「三级」资质（该企业可承接：无施工资质（仅劳务分包）），证企不一致
✘ 校验失败：1 项阻断（已备案队伍 1 项）…修复后可执行 npm run contractor:validate 单独重跑。
```

输出同时给出：**哪类队伍**（待审核/已备案/作业中 + 环节）、**哪支队伍**（编号+名称）、
**哪项条件不满足**（条件名 + 具体原因）。退出码：0 通过（允许有预警）、1 有阻断、2 用法/文件错误。

## 4. 幂等与存量保护语义

- prepare 重复执行结果**字节级一致**，不产生重复编号、不产生重复样例。
- **已备案、作业中**队伍在 prepare 时原样保留（含人工修正过的字段），不会被标准样例覆盖。
- 待审核、已清退同编号位以标准样例为准；非标准编号的已备案/作业中队伍追加保留并重排 id 防撞号；
  其余杂项随重新准备移除。
- 标准样例规约先自查全部通过才会写文件，任何一条不满足其所处环节条件都不落盘。
- 浏览器 localStorage 里的存量数据完全不被构建脚本触碰；页面上的状态流转由同一引擎实时拦截。

## 5. 新增一种资质类型时改哪里

只改 `contractor-rules.json`：

1. 新资质等级 → 加进 `qualificationGrades`（带 rank）；作业门槛变化再改 `assignQualification.grade`。
2. 新企业或企业资质范围变化 → 改 `enterprises`。
3. 新证书 → 加进 `certificates.catalog`；若变成必备证，名字同时加进 `certificates.required`。
4. 条件/环节本身变化 → 改 `conditions` 与 `stages`（引擎通用，无需改代码）。

改完跑 `npm run contractor:prepare && npm run contractor:validate`：
漏改任一处都会在构建期被分类报出；需要新样例时在 `contractor-sample-spec.mjs` 增加规约条目。
